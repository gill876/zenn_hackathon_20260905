AsobiAgent (アソビ・エージェント)

Add it to a LINE group. From dates → meeting station → places → booking prep, the AI does the legwork, and the friends decide.

✨ Gemini (Vertex AI)

Reads dates and wishes from the chat, and writes a one-line reason for each place based on the group's tastes.

🚇 Ekispert API (MCP)

One range search gives everyone's travel time. Picks the station where the farthest person travels least.

💬 LINE (Flex, LIFF)

No app, no sign-up. A calendar and buttons, so everyone takes part with a few taps.

🗣️ Opening line

"Hi! We built AsobiAgent, which lets a LINE group plan an outing without anyone having to organize it."

The problem

With friends, deciding is the hard part

😫 Dozens of messages

"When are you free?" "Where are you coming from?" "What do you feel like?" Dates, place and restaurant all land on one organizer.

⚖️ Unfair travel

The meeting point ends up near the organizer. Someone always has an hour each way or three transfers.

🗣️ The loudest voice wins

Asking everyone's tastes is a chore, so a friend who can't eat something goes unnoticed until it's booked.

🗣️ Script

"Planning dinner with friends takes dozens of LINE messages. Travel ends up unfair, and nobody really asks what everyone likes. An agent that joins the group takes that work over."

Autonomy

Four agents that read the situation

Agent 1 · Gemini

📅 Dates & wishes

Turns chat into fixed fields: day, time, wishes. When everyone has marked ○△×, it closes the poll itself and starts planning on the best day.

Agent 2 · Ekispert

🚇 Fair meeting station

One range search returns every reachable station with each person's average time. Ranks by farthest person, then spread, then average.

Agent 3 · Gemini

🍽 Places

Six places from HotPepper and Time Out covering everyone's likes. Drops anyone's dislikes and places closed at the planned time. Gemini writes why (✨).

Agent 4 · People decide

📞 Booking prep

A call script with date and party size, a call button and the booking page. The form-filling agent (Playwright + Gemini) only fills a demo form.

🧭 The bot decides the next step and shows only those buttons
🔎 Date set and stations known: it searches on its own
🔁 Say "something Japanese" and it re-reads and searches again
🗣️ Script

"Four agents watch the group and decide the next step: close the poll when everyone has answered, search as soon as the stations are known, and explain each place with Gemini."

Control, observability, security

Autonomous, but on a leash

🧭 People decide, nothing runs away

  • 📞The AI never calls or books. It prepares a script and a call button
  • 🔑Invite only. 1 place, 3 searches, 7 days and 10 people per group
  • 🧾Daily caps (LLM 300, searches 100, Places 30) and budget alerts
  • 🛡Signed webhooks. Duplicate events and stale buttons are ignored

🔎 Don't over-trust the LLM, and see what it does

  • 🧱The LLM only picks from candidate ids and fills fixed fields. Everything is checked against real data, so an injected prompt can't invent a place or an action
  • 🔁Vertex AI → GMI Cloud → rules. If the AI stops, the group doesn't
  • 📈No chat content in logs: only event types, which model answered in how long, and errors
  • 📊The admin sees today's usage with /stats
🗣️ Script

"The agents act on their own, but they never call or book. The LLM can only choose from real candidates, so prompt injection can't create a fake place. Caps and fallbacks keep it running and within budget."

Privacy

Doesn't read until called, deletes when done

🙈 Not listening

Idle chat is dropped unread. While gathering, only participants' messages are read.

🔐 Anonymous IDs

LINE user and group IDs are HMAC-hashed before they are stored.

🧹 Deleted automatically

Chat goes after the search, names and votes at the decision. Plans 7 days, polls 14, profiles 180, or delete any time.

🤐 No names to Gemini

The model sees counts like "2 like yakiniku". Chat lines are labelled "participant 1", not by name.

🗣️ Script

"It doesn't read the chat until it's called. IDs are anonymized, and once a place is decided, names and votes are deleted and the bot leaves the group."

Architecture
🗣️ Script

"LINE webhooks land on Cloud Run, which combines Gemini on Vertex AI, Ekispert and HotPepper. Data lives in Firestore and expires on its own."

Ekispert API (MCP)

One range search, a fair meeting station

🛡️ Timetable-free features only

  • ✅ No timetable (ダイヤ) search
  • ✅ One ekispert_api_search_ranges call gives everyone's average travel time
  • ✅ Names via get_stations, location via get_stations_from_geo (cached 90 days)

⚖️ How it chooses

① Shortest time for the farthest person → ② then the smallest spread → ③ then the lowest average.

Yokohama 42 · Kichijoji 39 · Nakameguro 40 · Kashiwa 44 min
➔ Meet at Akihabara: max 44 min, spread 5 (a real Ekispert result)
🗣️ Script

"We don't use timetable search. One range search tells us every reachable station and each person's travel time, and we pick the one that's easiest on the farthest person."

Implementation and extensibility

Runs small, grows as is

☁️ Serverless

Cloud Run (scales to zero), Firestore (TTL), Secret Manager, Cloud Build. No secrets in the code.

🧪 Tested

77 automated tests: the whole group flow, caps, deletion, fallbacks, the judges' code.

💴 Predictable cost

One or two Gemini calls per search. Replies only, so zero LINE push messages. Caps prevent runaway bills.

🔧 Easy to extend

Limits are environment variables. Add Time Out cities to go beyond Tokyo. Booking channels can be swapped in.

Tested with real friends: from the date poll to the meeting station, the decision and the call script, all inside LINE. What the test turned up (no date in the script, unclear next step) was fixed the same day.

🗣️ Script

"It runs on Cloud Run and scales to zero, and the caps keep costs predictable. Real friends used it, and we fixed what they ran into right away."
