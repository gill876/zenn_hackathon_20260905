AsobiAgent (アソビ・エージェント)

LINEグループ内で自然な雑談から「スケジュール調整」➔「公平な中間駅算出」➔「混雑回避スポット提案」➔「自律AI電話予約」までを全自動化する幹事支援マルチエージェント。

🚇 駅すぱあと MCP

規約遵守：ダイヤ情報不使用で公平な中間駅・移動時間を最適化

💬 LINE Flex Message

専用アプリ不要。LINEグループ内で直感的なカードUIを提供

⚡ GMI Cloud (Qwen3.8-Flash)

超高速LLM推論で会話抽出・穴場店舗選定を瞬時に自律実行

現場起点の切実な課題

東京の休日お出かけは、「幹事疲れ」と「人混み」の連続

😫 30往復以上のLINE調整

「誰がどこから来るか」「何時に集まるか」の調整だけでLINEが埋まり、誰も幹事をやりたがらない。

⚖️ 移動格差の不満

「自分だけ片道1時間かかる」「乗換が多すぎる」といった不満が生まれ、集まる場所の合意形成が困難。

☕ 週末東京の深刻な大混雑

渋谷・新宿の主要駅周辺はどこも満席。45分以上の行列に並び、落ち着いて会話すらできない。

🗣️ 発表用スクリプト

「友達とご飯に行こうとすると、LINEで何十通もやり取りし、移動時間の不公平さで揉め、結局渋谷の混雑した店で行列に並ぶことになります。AsobiAgentはこの負担をゼロにします。」

複数ステップの自律実行

4つの自律エージェントが連携するPipeline

Agent 1

📅 スケジュール同期

自然言語のLINE雑談から、参加メンバー・出発駅・食事の希望を自動抽出。

Agent 2 (駅すぱあと)

🚇 中間地点バランサー

全員の移動時間差が最小（±5分以内）になる最も公平な中間駅をAPIで自動算出。

Agent 3

🌿 混雑回避スポット探索

駅直結の混雑店を避け、静かに会話できる裏路地・隠れ家（穴場）を3軒厳選。

Agent 4

📞 自律AI電話予約

Web予約非対応の店舗へAIが直接日本語で架電。席を確保しLINEにチケット発行。

🗣️ 発表用スクリプト

「システムは4つのエージェントで構成されます。雑談から出発駅を読み取り、駅すぱあとAPIで公平な中間駅を割り出し、穴場を提案し、店舗への電話予約まで自律的に完遂します。」

ハッカソン規約遵守 & 技術的工夫

「駅すぱあと」APIのダイヤ情報不使用を完全徹底

🛡️ ハッカソン利用規約の遵守

  • ✅ ダイヤ探索（時刻指定探索）は一切不使用
  • ✅ ekispert_api_search_ranges による到達可能範囲探索を活用
  • ✅ searchType: plain（平均乗車時間探索）による駅間移動コストの比較
  • ✅ 時間調整やバッファ計算はLLMオーケストレーター側で自律処理

⚖️ 移動時間の公平性アルゴリズム

特定の参加者だけが遠くならないよう、最大移動時間と標準偏差（時間格差）をペナルティ化し、スコア90点以上の最適ハブ駅を決定。

横浜(44分) • 中目黒(39分) • 吉祥寺(37分) • 柏(42分)
➔ 最適解:「御徒町 / 上野」移動差わずか ±4分！
🗣️ 発表用スクリプト

「ハッカソンの規約に従い、時刻指定のダイヤ検索は一切使っていません。範囲探索と平均探索のみを用いて、全員の移動時間がほぼ均等になる公平なハブ駅を高速に算出しています。」

技術スタック & 認知負荷を下げるUX

外部アプリ不要 — LINE Flex UI & GMI Cloud

📱 LINE Flex Message

URL遷移や専用アプリ不要。LINEグループ内にリッチな確認カード、中間駅グラフ、穴場カルーセル、予約チケットを直接描画。

⚡ GMI Cloud (Qwen3.8-Flash)

100万トークン対応の高速GPU推論を活用。並列処理と軽量化により、複数往復の会話でも数秒での応答を実現。

☁️ Google Cloud Ready

Cloud Runへのコンテナデプロイ対応。Google Cloudインフラストラクチャ上でスケーラブルに動作。

🗣️ 発表用スクリプト
